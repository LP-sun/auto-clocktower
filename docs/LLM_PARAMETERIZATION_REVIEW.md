# LLM 参数化重构审查

## 范围与原则

本次基线合并 `codex/publish-work-2026-09-10` 与 `feature/phase36-world-reasoning`。目标覆盖规则引擎输入输出、bridge 调度、玩家上下文与记忆、模型后端和说书人裁量。参数化用于表达状态、合法行动、通信、玩家倾向与资源限制；身份推断、证据评价、欺骗策略和行动选择仍由 LLM 完成。

数学模拟中的参数是可复用的实验控制变量，不是已由真人数据标定的心理量表。模拟中的胜率、softmax 温度或 belief_accuracy 不等于 LLM 的实测能力，也不能证明调整这些参数一定改善真实对局。

## 基线问题

| 优先级 | 问题及原始位置 | 影响 | 重构要求 |
|---|---|---|---|
| P0 | `semantic-memory.cjs` 用自然语言正则抓取角色声明 | 否认、引用和模糊表述可能被当作自称；中文表达变化导致漏记 | 显式通信字段与来源、受众；声明永远不等于真实角色 |
| P0 | 结构化控制、聊天文本与私有决策摘要共用响应外壳 | 新字段容易被透传至错误受众或遗失 | 统一验证，公开内容与私有记忆更新分别路由 |
| P0 | `memoryUpdate` 可保存，但原提示只要求四个顶层字段 | LLM 不知道如何持久更新信念，长期状态可能空转 | 提供一致的有界更新协议，验证席位和证据可见性 |
| P1 | `run.cjs`、`context-builder.cjs`、角色 JSON、上游 introduction 和后端各自写提示 | 重复规则、术语混杂、策略强制倾向难审查 | 公共词表、规则来源与接口说明集中管理 |
| P1 | 模型、重试、上下文与记忆窗口散落在环境变量及常量中 | 难以复现实验，局部调整不能覆盖调用链 | 统一配置、启动验证、记录实际生效参数 |
| P1 | LLM 玩家没有对应数学模拟的人格与技能配置 | 不同玩家策略差异无法按同一组变量控制 | 可复现的逐席位配置；参数作为倾向交给 LLM |
| P1 | 说书人的模型输出与引擎自由裁量边界需要显式协议 | 自由文本解释可能与选择不一致 | 只允许法律域内选择，以引擎结算为事实 |
| P1 | 旧后端和直接调用入口可能走不同上下文路径 | 仅修改 bridge 不足以统一所有 LLM 行为 | 检查上游类型、后端输入验证和下游接口 |
| P2 | README 偏重 Windows 编译方式 | 跨平台验证成本高 | `node bridge/verify.cjs` 编译并运行离线回归 |

## 验证边界

离线测试可以验证协议、参数传递、信息隔离和引擎回归，不能验证 LLM 是否按人格倾向行动、对局真实性、胜率改善或 token 节省。本次不把 fixture 标记为真实模型实验。

真实模型对比应固定代码版本、配置、席位组合和种子集合，分别统计请求与输出 token、重试率、非法动作率、私聊占比、身份公开时点、重复发言比例及对局完成率。模型有非确定性，应比较多局分布，不能用单个种子的胜负证明优劣。
